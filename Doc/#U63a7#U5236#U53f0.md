# 控制台宿主 · 需求文档

**版本**：0.0.1
**状态**：草案
**适用**：桌面 / Unity 运行时的命令行入口，作为 RPC 执行器的宿主

---

## 1. 概述

### 1.1 背景
需要一个轻量控制台宿主，让用户以命令行形式调用 RPC 服务，并具备子命令树、Tab 补全、动态候选等能力。需兼容 Unity 运行时（无 `Console.ReadKey` 光标控制、无 GNU Readline 依赖）。

### 1.2 目标
- 提供 `<service> <sub...> <args...>` 形式的命令输入与执行
- 支持**路径式声明**的树形子命令（`listen autostart on`）
- 支持**位置参数**与**动态补全**
- 补全系统与命令树**解耦**：同一棵树同时驱动分发与补全
- 通过源代码生成器从用户类自动生成命令树，用户代码不含任何手工构树语句
- 提供 `CommandBase` 基类，统一命令实现的依赖获取与输出方式

### 1.3 非目标（0.0.1）
- 不支持 `--option` / `-o` 形式的命名选项（全部以子命令表达）
- 不内置行编辑器（光标移动、历史记录由宿主 UI 提供）
- 不做命令别名

---

## 2. 术语

| 术语 | 含义 |
|---|---|
| 命令树 | 由 `ConsoleCommand` 组成的层级结构 |
| 子命令 | 树中非根节点，名字即路径段 |
| 根处理器 | 命令节点自身的可执行方法（`[RootCommand]`） |
| 位置参数 | 命令后按顺序出现的参数，无前缀 |
| 补全源 | 返回候选字符串的委托 |
| CompletionContext | 补全时提供的上下文（已输入参数、当前前缀等） |
| CommandBase | 命令类的可选基类，提供依赖注入与统一输出 |

---

## 3. 总体架构

```
┌────────────────────────────────────────────────────┐
│ 宿主 UI（Console / Unity UI）                      │
│  - 读一行 / 渲染候选 / Tab 选中                    │
└───────────────┬───────────────────┬────────────────┘
                │ tokens            │ CommandCompletion.Get
┌───────────────▼───────────────────▼────────────────┐
│ ConsoleCommand（树）                               │
│  ├─ Subcommands                                    │
│  ├─ Arguments → CompletionProvider                 │
│  └─ Handler → 命令实例（可选继承 CommandBase）      │
└───────────────┬────────────────────────────────────┘
                │ RpcRequest
┌───────────────▼────────────────────────────────────┐
│ RpcExecutor（见 RPC 需求文档）                     │
└────────────────────────────────────────────────────┘
```

## 4. 功能需求

### FR-1 命令模型
- **FR-1.1** 命令以树组织，节点类型为 `ConsoleCommand`，字段：`Name`、`Description`、`Arguments`、`Subcommands`、`Handler`。
- **FR-1.2** 节点可为三种形态：
  - **纯叶子**：有 `Handler`，无子命令（如 `listen on`）
  - **纯组**：无 `Handler`，有子命令（如 `autostart` 中间节点）
  - **混合**：有 `Handler` 且有子命令（如 `listen` 回车打状态、又可下钻）
- **FR-1.3** 子命令的中间节点可由生成器根据路径**自动创建**，用户无需声明。

### FR-2 命令基类 `CommandBase`
- **FR-2.1** 提供抽象基类 `CommandBase`，命令实现类**可选**继承。不继承亦可（生成器不强制）。
- **FR-2.2** `CommandBase` 暴露 `CommandContext Context { get; internal set; }`，由生成器在创建命令实例后注入。
- **FR-2.3** `CommandContext` 至少包含：
  ```csharp
  public sealed class CommandContext
  {
      public IConsoleRenderer Renderer { get; init; }
      public IServiceProvider Services { get; init; }
      public ConsoleCommand Command { get; init; }
      public IReadOnlyList<string> Tokens { get; init; }
  }
  ```
- **FR-2.4** `CommandBase` 提供受保护便捷成员：
  ```csharp
  protected IConsoleRenderer Console { get; }
  protected IServiceProvider Services { get; }
  protected void Print(string message);
  protected void PrintError(string message);
  protected T GetService<T>();
  ```
- **FR-2.5** `CommandBase` 提供可选生命周期钩子（虚方法，默认空实现）：
  ```csharp
  protected virtual void OnCommandEntering();
  protected virtual void OnCommandExiting();
  protected virtual void OnCommandFailed(Exception ex);
  ```
  生成器必须在调用命令方法前后自动调用 `OnCommandEntering` / `OnCommandExiting`；异常时调用 `OnCommandFailed` 后重新抛出（交给执行器转错误码）。
- **FR-2.6** `CommandBase` 必须不引入对任何第三方库的依赖。

### FR-3 命令声明（特性）
- **FR-3.1** 类上标注 `[ConsoleCommand("name", "desc")]` 表示该类的根命令。
- **FR-3.2** 方法上标注 `[ConsoleCommand("path", "desc")]` 表示子命令，`path` 支持空格分隔的多段路径（如 `"autostart on"`）。
- **FR-3.3** 方法上标注 `[RootCommand]` 表示该方法是类根命令的直接处理器（无子命令名）。
- **FR-3.4** `[ConsoleCommand]` 的 path 不得为空字符串；生成器遇空 path 必须报 `Error`。
- **FR-3.5** 同一类中 `[RootCommand]` 最多一个，多个报 `Error`。
- **FR-3.6** 同一父节点下子命令名不得重复，重复报 `Error`。

### FR-4 位置参数
- **FR-4.1** 方法签名中**不带任何特性**的参数自动视为位置参数，按出现顺序编号。
- **FR-4.2** 位置参数名称直接取 `Parameter.Name`，**不允许**通过特性重命名。
- **FR-4.3** 框架注入类型（`CancellationToken`、`ILogger`、`IServiceProvider`）自动排除，不参与位置参数排序。
- **FR-4.4** 参数类型转换规则由 RPC 层的 `IArgumentConverter` 负责（Console 不重复实现）。
- **FR-4.5** 参数个数不足时返回错误提示："缺少参数: {name}"；过多时："参数过多"。

### FR-5 动态补全
- **FR-5.1** 位置参数可通过 `[CompletionSource(nameof(Method))]` 绑定动态补全方法。
- **FR-5.2** 补全方法签名必须为 `IEnumerable<string> Method(CompletionContext ctx)`；签名不符时生成器报 `Error`。
- **FR-5.3** 未绑定 `CompletionSource` 的位置参数**默认静默**（返回空候选），例如 `sum 1 2` 的 `1`、`2` 不产生提示。
- **FR-5.4** 子命令候选由命令树自动提供，无需用户声明。
- **FR-5.5** 若命令类继承 `CommandBase`，补全方法可作为实例方法访问 `Context`（例如根据 `Context.Services` 查询候选），生成器必须通过 `instance.<method>` 调用。

### FR-6 补全算法
- **FR-6.1** 补全入口为 `CommandCompletion.Get(ConsoleCommand root, IReadOnlyList<string> tokens)`。
- **FR-6.2** `tokens[0]` 为根命令名，中间为完整 token，**`tokens[^1]` 为正在输入的前缀**（行尾空格时追加空字符串 token）。
- **FR-6.3** 算法规则：
  - 若尚未消耗任何位置参数 → 先匹配子命令前缀
  - 再按已消耗位置参数数量，取对应参数的 `CompletionProvider` 生成候选
  - provider 为 null → 不产生候选
  - 完整 token 能匹配子命令则下钻并**重置位置参数计数**
- **FR-6.4** 候选必须去重、按 Ordinal 排序。
- **FR-6.5** `CompletionContext` 至少包含：`PriorArguments`（已输入的位置参数）、`CurrentPrefix`、`AllTokens`。
- **FR-6.6** 补全算法必须无副作用，可被并发调用。

### FR-7 分发与执行
- **FR-7.1** 输入行先经 `SplitArgs` 切分为 token，支持双引号包裹含空格的参数（`"hello world"`）。
- **FR-7.2** 从根命令沿 token 下钻：非最后 token 能匹配子命令则下钻，否则作为位置参数收集。
- **FR-7.3** 到达叶节点后调用 `Parse` 生成 `ParseResult`，参数按名映射。
- **FR-7.4** 执行前由宿主把 `(service, method, args)` 封装为 `RpcRequest`，交给 `RpcExecutor.ExecuteAsync`。
- **FR-7.5** 执行结果输出规则：
  - `Success=true` → 输出 `FormatResult(Result)`（字符串原样，复杂对象 JSON）
  - `Success=false` → 输出 `!! [{Error.Code}] {Error.Message}`
- **FR-7.6** 内置命令 `help`（列出命令树）、`exit` / `quit`（退出）。

### FR-8 与 RPC 的映射
- **FR-8.1** Console 命令可**手动绑定**到 RPC 服务（命令 Handler 内构造 `RpcRequest`）。
- **FR-8.2** （可选，M4）支持 `[RpcCommand("service", "method")]` 特性，由生成器自动把命令节点映射为 RPC 调用。
- **FR-8.3** Console 层不得直接引用 `ServiceDescriptor`，只能通过 `RpcExecutor` 公共 API 交互。

### FR-9 源代码生成器
- **FR-9.1** 使用 `IIncrementalGenerator` + `ForAttributeWithMetadataName` 定位标注类。
- **FR-9.2** 为每个标注类生成 `<ClassName>Builder`，提供 `Build(Func<T> factory, CommandContext context) -> ConsoleCommand`。
- **FR-9.3** 若命令类继承 `CommandBase`，生成器必须在创建实例后**立即设置** `instance.Context = context`，并在调用命令方法前后触发生命周期钩子。
- **FR-9.4** 路径按空格拆分，中间节点自动创建；同路径段复用同一节点。
- **FR-9.5** 生成代码必须使用 `global::` 全限定名，避免命名冲突。
- **FR-9.6** 生成器必须提供以下诊断：
  - `CONSOLE001`：子命令 path 为空
  - `CONSOLE002`：`CompletionSource` 指向的方法不存在
  - `CONSOLE003`：`CompletionSource` 方法签名不符
  - `CONSOLE004`：同父节点子命令重名
  - `CONSOLE005`：多个 `[RootCommand]`

## 5. 示例

### 5.1 继承 `CommandBase` 的命令

```csharp
[ConsoleCommand("listen", "查看或控制网络监听器")]
public sealed class ListenCommand : CommandBase
{
    private readonly ListenService _service;
    public ListenCommand(ListenService svc) => _service = svc;

    [RootCommand]
    public void Status()
    {
        Print($"[listen] 状态     : {(_service.IsRunning ? "ON" : "OFF")}");
        Print($"[listen] 自启动   : {(_service.AutoStart ? "YES" : "NO")}");
    }

    [ConsoleCommand("on", "开启监听")]
    public void On() { _service.Start(); Print("[listen] 已启动。"); }

    [ConsoleCommand("off", "关闭监听")]
    public void Off() { _service.Stop(); Print("[listen] 已停止。"); }

    [ConsoleCommand("autostart on", "开启自启动")]
    public void AutoStartOn()
    {
        _service.AutoStart = true;
        Print("[listen] 自启动已开启。");
    }

    [ConsoleCommand("autostart off", "关闭自启动")]
    public void AutoStartOff()
    {
        _service.AutoStart = false;
        Print("[listen] 自启动已关闭。");
    }
}
```

### 5.2 不继承 `CommandBase` 的命令（生成器同样支持）

```csharp
[ConsoleCommand("sum", "两数相加")]
public sealed class SumCommand
{
    [RootCommand]
    public int Sum(int a, int b) => a + b;   // a、b 无 provider → 静默
}
```

### 5.3 动态补全

```csharp
[ConsoleCommand("connect", "连接服务器")]
public sealed class ConnectCommand : CommandBase
{
    private readonly List<string> _servers = new() { "alpha", "beta", "gamma" };
    private readonly HashSet<string> _connected = new();

    [RootCommand]
    public void Connect([CompletionSource(nameof(GetServers))] string server)
    {
        _connected.Add(server);
        Print($"[connect] 已连接: {server}");
    }

    private IEnumerable<string> GetServers(CompletionContext ctx)
        => _servers.Where(s => !_connected.Contains(s)
                            && s.StartsWith(ctx.CurrentPrefix, StringComparison.OrdinalIgnoreCase));
}
```

### 5.4 生成结果（节选）

```csharp
public static class ListenCommandBuilder
{
    public static ConsoleCommand Build(
        Func<ListenCommand> factory,
        CommandContext context)
    {
        var instance = factory();
        instance.Context = context;                          // ← CommandBase 注入

        var cmd_listen_autostart_on  = new ConsoleCommand("on", "开启自启动")
        {
            Handler = r => { instance.OnCommandEntering();
                             try { instance.AutoStartOn(); }
                             finally { instance.OnCommandExiting(); }
                             return null; }
        };
        // ... 其余节点省略
    }
}
```

## 7. 非功能需求

| 编号 | 需求 | 指标 |
|---|---|---|
| NFR-1 | Unity 兼容 | 不依赖 `Console.ReadKey`、不依赖第三方 ReadLine 库；核心逻辑可在 IL2CPP 下运行 |
| NFR-2 | 补全响应速度 | 100 命令规模下，`CommandCompletion.Get` 单次调用 < 100μs |
| NFR-3 | 无反射 | 命令树构建与分发均为生成代码，不依赖 `MethodInfo.Invoke` |
| NFR-4 | 可测试性 | `CommandCompletion.Get`、`ConsoleCommand.Parse` 为纯函数，可单元测试 |
| NFR-5 | 诊断 | 所有生成器错误有明确 code、位置、可操作提示 |
| NFR-6 | 依赖 | 核心仅依赖 BCL，不引入 NuGet |

## 8. 约束与假设

- **C-1** 命令结构在编译期确定（生成器路径）。
- **C-2** 不支持命名选项，所有能力以子命令表达。
- **C-3** 位置参数名与 C# 参数名强绑定，不使用特性重命名。
- **C-4** 补全的候选来源仅限：子命令、位置参数 provider；不支持"选项补全"。
- **C-5** 行编辑与候选展示由宿主实现，Console 核心不假设终端能力。
- **C-6** `CommandBase` 是可选基类，不继承时功能不受影响；但继承后可获得生命周期钩子与 `Context`。

## 9. 验收标准

1. 声明 `ListenCommand`（含 `[RootCommand] Status`、`on`、`off`、`autostart on`、`autostart off`），生成器产出的树结构为：
   ```
   listen
     on
     off
     autostart
       on
       off
   ```
2. `listen` 回车执行 `Status` 打印状态。
3. `listen autostart off` 正确关闭自启动。
4. `CommandCompletion.Get(root, ["listen", ""])` 返回 `["on","off","autostart"]`。
5. `CommandCompletion.Get(root, ["listen","autostart",""])` 返回 `["on","off"]`。
6. `CommandCompletion.Get(root, ["sum","1",""])` 返回空（`b` 无 provider）。
7. `CommandCompletion.Get(root, ["connect",""])` 返回 provider 动态结果，且随已连接状态变化。
8. 继承 `CommandBase` 的命令类可通过 `Print` 输出、可通过 `Services.GetService<T>()` 获取服务。
9. 生命周期钩子 `OnCommandEntering` / `OnCommandExiting` 在每次命令执行前后各调用一次；抛异常时 `OnCommandFailed` 被调用一次。
10. `[ConsoleCommand("", ...)]` 触发 `CONSOLE001` 编译错误。
11. `[CompletionSource("NotExist")]` 触发 `CONSOLE002`。
12. 在 `Console.IsInputRedirected=true` 时（管道输入）仍可正常执行命令。
13. Unity 2022 LTS IL2CPP 构建通过，命令树与补全在运行时可用。

## 10. 里程碑

| 阶段 | 内容 |
|---|---|
| M1 | 模型 + `Parse` + `SplitArgs` + 基础分发（手写命令树）；`CommandBase` / `CommandContext` 定义 |
| M2 | 源代码生成器（路径建树 + RootCommand + 参数收集 + CommandBase 注入）上线 |
| M3 | 补全算法 + `CompletionSource` 动态 provider + 诊断 |
| M4 | `ILineEditor` / `IConsoleRenderer` 抽象；Unity 适配示例 |
| M5 | 与 `RpcExecutor` 联调；`[RpcCommand]` 自动映射（可选） |
